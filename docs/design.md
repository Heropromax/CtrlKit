# 设计说明

本文维护设计意图与取舍。当前接口事实见 [API 文档](api.md)，修改要求见[贡献指南](../CONTRIBUTING.md)，尚未实现的工作见[路线图](roadmap.md)。

## 背景与目标

CtrlKit 来自作者在机器人与高性能控制系统开发中的需求：逐步减少对 MATLAB/Simulink 生态的依赖，保留模型化思考方式，同时获得接近 PyTorch 模块组合的代码使用体验。

目标是提供易组合、可直接部署的实时控制基础积木。部署对象包括现代嵌入式和桌面系统，具体工具链、标准库和芯片性能需要分别验证。

库保持小而直接。信号可视化、仿真以及与 MuJoCo、Julia ModelingToolkit 等环境的配合属于未来外围设施的方向，不是当前核心库的已实现能力。

## 架构与依赖

```text
ctrlkit.hpp：Vec、scalar_t、基础运算、常量
    ↑              ↑                ↑
math.hpp       quat.hpp        dynamic.hpp
逐元素数学      姿态与旋转        有状态离散模块
```

三个功能头文件依赖基础头文件，当前互不依赖。ctrlkit.hpp 不是包含所有功能的总入口。应用包含所需模块，自行组合信号流。

核心采用头文件实现、固定尺寸存储、模板和值语义，避免建立运行期对象图或统一调度框架。

## 数据类型保持简单

Vec、Quat 优先保持聚合类型，支持直观的花括号初始化。其成员主要承载数据、运算符与必要的数据访问。当前 `Quat::conj()` 是已有的成员接口。

点积、模长、归一化和逐元素数学等计算优先使用自由函数，避免持续扩张成员接口，也方便通过公开数据和运算符扩展能力。自由函数位于 ctrlkit 命名空间，适用时可通过 ADL 查找。

保留聚合性意味着不引入用户声明的构造函数；元素类型转换通过显式转换运算符完成。

## 显式语义

- 不提供标量到向量的隐式转换，避免意外提升和重载歧义。
- 向量元素类型转换为显式操作，让精度变化可见。
- 四元数复合旋转写明 `q = q * r` 或 `q = r * q`，保持乘法顺序可见。
- 除法按除法语义实现，不主动改为倒数乘法；浮点优化策略交给使用者的编译选项。

## 信号与系数类型分离

动态模块只有一个信号类型参数 T，系数用 `scalar_t<T>`，状态和输入输出用 T：

```cpp
template <typename T>
class MyModule
{
public:
    using Scalar = ctrlkit::scalar_t<T>;
private:
    Scalar coefficient{};
    T state{};
};
```

标量和向量复用同一套实现。向量各轴共享系数，不隐含支持每轴不同的采样周期或滤波参数；需要不同参数时组合多个实例。

动态模块统一采用 step(input)、reset(value) 和可选初值。对象自己持有状态，应用决定何时推进一步。

## 数值行为与实时约束

二阶低通采用带频率预畸变的双线性变换和 TDF-II 状态实现。reset 对齐直流稳态，减少初始化引入的瞬态。具体参数、阻尼与边界行为以 API 文档为准，避免将某个配置的性质推广成所有配置的保证。

核心库的设计约束：

- 不依赖堆分配，状态和临时存储尺寸在编译期确定。
- 不抛异常、不依赖 RTTI 或虚函数，采用静态组合。
- 运算规模由固定维度或模板参数限定，不引入运行期无界工作量。
- 明确每个接口的合法输入、初值、退化情况和错误参数策略。

这些约束针对 include/ctrlkit/，不要求测试和外围工具遵循相同资源限制。无分配和工作量有界不等于已经完成最坏执行时间认证，硬件、数学库和编译选项均影响时序。

非法参数保护仍有缺口，不能将“边界不产生 NaN”视为全库已实现保证。零向量模长返回零，四元数归一化有小模长兜底，两者是不同接口的行为。

## constexpr 与头文件独立性

能合理标记 constexpr 的接口尽量标记，但实际常量求值受语言标准、数学库和工具链限制。当前 Lpf2nd 构造函数未标记 constexpr。

每个头文件应直接包含自己用到的标准库头文件，不依赖传递包含。该原则是维护要求，不表示当前实现已完全符合；现存缺口记录在路线图。

Vec3f、pi_f 等短名称服务使用体验。内部数学常量优先使用 std::numbers，降低实现对外部便捷别名的依赖。

## 功能边界与支持方向

核心不提供完整 PID、轨迹规划、统一调度或仿真求解器。使用者组合基础模块形成自己的控制律；这些边界来自当前项目定位，不代表相应算法在控制领域不重要。

高阶滤波、轴角转换和定点数目前优先级较低，是否实现取决于实际需求。Delay 暂无明确需求，与长期排除的能力区分记录。

目标工具链基线为 GCC 12+、Clang 14+、MSVC VS2022，保留现代 C++ 表达能力。IAR、Keil MDK / Arm Compiler 6、TI C2000 和传统 8/16 位 MCU 暂不作为适配目标；这是当前范围选择，不构成对所有版本能力的判断。

库不承担功能安全认证或系统级安全功能。外围安全架构由实际系统负责设计。
